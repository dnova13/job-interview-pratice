# 1단계 답변 분석 기능 계획

녹음·녹화 중인 카메라·마이크 스트림을 **내 컴퓨터 안에서** 분석해 목소리 톤·크기·침묵, 시선, 고개 움직임을 측정하고 점수와 조언을 보여 준다. 인터넷 연결이나 외부 서버는 쓰지 않는다.

> **점수의 성격**: 나쁜 습관을 찾아 주는 **참고용** 도구다. 각 지표의 "방향"(단조로운 목소리, 시선 회피, 과한 고개 움직임은 좋지 않다)은 연구·코칭 관행으로 뒷받침되지만, **숫자 기준은 대부분 경험치이거나 임의로 정한 값**이다. 그래서 화면에서 점수를 보여 주는 모든 곳에 **"참고용"** 표시를 붙이고, 점수와 함께 실제 측정값과 기준을 같이 보여 준다. 절대 점수보다 **내 점수 추이**를 중심으로 본다.

## 1. 범위

| 포함 (1단계) | 제외 (2단계 이후) |
|---|---|
| 목소리 톤(음 높이) 변화, 음량, 음량 안정성, 침묵 | 말하기 속도(분당 음절), 군말("음", "어") — Whisper 필요 |
| 시선 점 표시, 정면 응시율 | 화면 좌표 단위의 정밀 시선 추적(보정 필요) |
| 고개 끄덕임·좌우 흔들림 횟수 | 표정·감정 분석 |
| 항목별 점수, 종합 점수, 조언 문구 | 답변 내용 평가 |
| 질의별 점수 기록과 추이 | |

## 2. 사용 기술

| 영역 | 기술 | 용도 | 비고 |
|---|---|---|---|
| 얼굴 분석 | **MediaPipe Face Landmarker** (`@mediapipe/tasks-vision` 1.2.x) | 얼굴 점 478개(눈동자 10개 포함), 머리 자세 행렬, 눈 방향 blendshape | Google, Apache-2.0. WASM + WebGL(GPU)로 렌더러에서 실행. 모델 `face_landmarker.task` 약 3.6MB |
| 음 높이 | **pitchy** 4.x (McLeod Pitch Method) | 프레임별 기본 주파수(F0)와 신뢰도 | 의존성 없는 작은 라이브러리 |
| 오디오 입력 | **Web Audio API** (`AudioContext`, `AnalyserNode`) | 마이크 스트림에서 파형 샘플 추출, RMS 음량 계산 | 브라우저 내장 |
| 영상 프레임 | `HTMLVideoElement.requestVideoFrameCallback` | 카메라 프레임마다 분석 호출(초당 10~15회로 제한) | 브라우저 내장 |
| 오버레이 | `<canvas>` 2D | 카메라·재생 영상 위에 눈동자 점, 시선 점, 정면 표시 | |
| 차트 | 직접 그린 SVG 스파크라인 | 리포트의 음 높이·음량·고개 각도 그래프, 질의별 점수 추이 | 별도 차트 라이브러리 없이 구현 |
| 계산 로직 | TypeScript 순수 함수 | 시계열 → 지표 → 점수 | 단위 테스트 대상 |
| 테스트 | **Vitest** + Electron e2e 스크립트 | 지표 계산 단위 테스트, 가짜 카메라·마이크로 통합 테스트 | Chromium `--use-file-for-fake-video-capture`, `--use-file-for-fake-audio-capture` |

## 3. 처리 흐름

```
카운트다운 ──▶ 기준값 측정 (배경 소음, 정면 기준 자세)
     │
녹음 시작 ──▶ 같은 MediaStream을 두 분석기에 연결
     │          ├─ AudioAnalyzer: 50ms마다 RMS·F0 → 오디오 시계열
     │          └─ FaceAnalyzer: 프레임마다 머리 각도·시선 → 얼굴 시계열
     │          (시간은 Recorder의 녹음 시간 기준, 일시정지 구간 제외)
     │
     ├─ 실시간: 카메라 위 오버레이 (시선 점, "정면/측면" 배지)
     │
녹음 완료 ──▶ 시계열 → 지표 계산 → 점수·조언
     │
다시 듣기 ──▶ 분석 리포트 표시, 영상 재생 시 시간에 맞춰 시선 점 다시 그림
     │
저장 ──▶ 요약 점수: store.json의 질의별 기록 (최근 20회)
         시계열: 녹음 파일을 저장할 때 같은 이름의 .analysis.json으로 함께 저장 (선택)
```

- 카운트다운 동안 측정한 기준값으로 카메라 위치(모니터 위·옆)와 방 소음 차이를 보정한다.
- 이때 카운트다운 화면에 **"카메라 렌즈를 보세요"**라고 안내한다. 화상 면접에서는 화면이 아니라 렌즈를 볼 때 눈을 맞춘 것처럼 보이므로, 렌즈를 보는 자세를 "정면" 기준으로 삼는다.
- MediaRecorder 녹음과 분석은 서로 독립적이다. 분석이 느려지거나 실패해도 녹음은 그대로 진행된다.

## 4. 측정 지표와 계산 방법

> 기준값은 발표·면접 코칭에서 흔히 쓰는 **경험치**이며 과학적 표준이 아니다. 설정에서 조정할 수 있게 한다.
> "근거" 열: **연구** = 방향이 연구로 뒷받침됨, **코칭** = 흔한 코칭 조언, **임의** = 숫자를 이 앱에서 정함. 숫자 자체가 연구로 정해진 항목은 없다.

### 4.1 목소리

| 지표 | 계산 | 적정 기준 (초기값) | 근거 |
|---|---|---|---|
| 발화 구간 | RMS가 (배경 소음 + 10dB)보다 크면 말하는 중 | — | — |
| 평균 음량 | 발화 구간 RMS 평균 (dBFS) | 너무 작음 경고: 배경 소음 + 15dB 미만 | 임의 |
| 음량 안정성 | 발화 구간 RMS의 표준편차 | 6dB 이하 | 임의 |
| 끝 처짐 | 마지막 20% 구간 평균 음량 − 전체 평균 | −4dB보다 작게 떨어지면 경고 | 코칭 |
| 음 높이 변화 | 신뢰도 0.9 이상인 F0(75~400Hz)를 본인 중앙값 기준 반음(semitone)으로 바꾼 뒤 표준편차 | 2~4반음 (1.5 미만: 단조로움, 5 초과: 들뜸) | 연구 (숫자는 일반 대화의 높낮이 폭) |
| 침묵 | 비발화 구간이 **3초 이상** 이어진 횟수 (짧은 쉼은 좋은 습관이라 세지 않음) | 답변 1분당 2회 이하 | 코칭 |
| 발화 비율 | 발화 시간 ÷ 전체 녹음 시간 | 70% 이상 | 임의 |
| 답변 시작 지연 | 녹음 시작부터 첫 발화까지 시간 | **5초 이하** (생각하는 시간은 감점하지 않음) | 코칭 |

### 4.2 시선

| 지표 | 계산 | 적정 기준 (초기값) | 근거 |
|---|---|---|---|
| 얼굴 감지율 | 얼굴이 잡힌 프레임 비율 | 90% 미만이면 "카메라 위치·조명 확인" 안내 | — |
| 머리 방향 | 머리 자세 행렬 → yaw(좌우)·pitch(상하)·roll(기울기) 각도 | — | — |
| 눈 방향 | blendshape `eyeLookIn/Out/Up/Down` (좌·우 눈)으로 눈동자 방향 추정 | — | — |
| 정면 판정 | (머리 방향 + 눈 방향 − 렌즈 기준 자세)가 좌우 ±10°, 상하 ±8° 안 | — | 임의 |
| 정면 응시율 | 정면 프레임 ÷ 얼굴 감지 프레임. **1.5초 이하로 잠깐 시선을 돌린 구간은 정면으로 계산** | **60~70% 이상** | 연구 (말하는 사람은 생각할 때 시선을 돌리는 게 자연스러워 70%보다 엄격하게 잡지 않음) |
| 시선 이탈 | 정면이 아닌 상태가 1.5초보다 길게 이어진 횟수 | 1분당 3회 이하 | 임의 |

- **시선 점**: 눈동자 점(얼굴 점 468·473번)을 화면에 찍고, 두 눈 가운데에서 시선 방향으로 뻗은 위치에 시선 점을 하나 더 찍는다. 정면이면 초록, 벗어나면 주황으로 표시한다.
- 화면의 정확한 좌표를 맞히는 것이 아니라 **카메라를 보고 있는지**를 판단하는 것이 목적이다.

### 4.3 고개 움직임

| 지표 | 계산 | 적정 기준 (초기값) | 근거 |
|---|---|---|---|
| 끄덕임 | pitch 각도가 **4° 이상** 내려갔다 다시 4° 이상 올라오면 1회. 움직임 폭의 절반 높이에서 잰 길이가 0.1~1초일 때만 (천천히 숙이는 동작 제외). 0.3초짜리 빠른 끄덕임도 잡도록 평활화는 하지 않고 초당 15회 측정 | 1분당 4회 이하 | 코칭 |
| 좌우 흔들림 | yaw 각도에 같은 방식 적용 (4°) | 1분당 3회 이하 | 코칭 |
| 고개 기울기 | roll 각도 평균의 절댓값 | 7° 이하 | 임의 |
| 전체 움직임 | yaw·pitch 각도의 표준편차 | 수치만 표시 | — |

## 5. 점수 체계

- 각 지표를 0~100점으로 바꾼다. 적정 범위 안이면 100점이고, 범위를 벗어난 만큼 직선으로 깎아 기준의 2배를 벗어나면 0점이 된다.
- 항목 점수와 가중치:

| 항목 | 들어가는 지표 | 가중치 |
|---|---|---|
| 목소리 | 음 높이 변화, 음량·안정성, 끝 처짐 | 30% |
| 말의 흐름 | 침묵, 발화 비율, 답변 시작 지연 | 20% |
| 시선 | 정면 응시율, 시선 이탈 | 30% |
| 자세 | 끄덕임, 좌우 흔들림, 기울기 | 20% |

- 가중치는 임의로 정한 값이며 설정에서 바꿀 수 있게 한다.
- **종합 점수** = 가중 평균. 얼굴이 잡히지 않았거나 녹음 시간이 10초보다 짧으면 해당 항목은 "측정 불가"로 두고 가중치에서 뺀다.
- **조언 문구**: 점수가 가장 낮은 2~3개 지표에 대해 규칙 기반으로 보여 준다.
  - 예: "고개를 1분에 9번 끄덕였습니다. 끄덕임을 줄이면 더 차분해 보입니다."
  - 예: "답변 중 38%는 카메라가 아닌 곳을 봤습니다. 카메라 렌즈를 면접관의 눈이라고 생각해 보세요."

## 6. 결과를 알려 주는 방식

결과는 네 곳에서 보여 주며, 점수가 나오는 모든 곳에 **"참고용"** 표시를 붙인다.

| 위치 | 내용 |
|---|---|
| ① 녹음 중 카메라 위 | 눈동자 점과 시선 점(정면 초록, 이탈 주황), "정면/측면" 배지, 끄덕임 횟수. 연습에 방해되지 않게 작게 표시하고 설정에서 끌 수 있음 |
| ② 다시 듣기 질문 영역 | 분석 리포트: 종합 점수와 "지난번보다 +N", 항목별 점수 막대, 각 항목의 **실제 측정값과 기준**(예: "끄덕임 9회/분 (기준 4회 이하)"), 점수가 낮은 지표에 대한 조언 2~3개 |
| ③ 리포트의 "자세히" | 타임라인: 시선 정면/이탈 띠, 음 높이·음량 선, 끄덕임 표시를 시간 축에 나란히 그림. **구간을 누르면 그 장면으로 재생 위치 이동**. 영상이면 재생 중 시선 점도 다시 그림 |
| ④ 질의 목록 | 질의별 최근 점수, 점수 추이 스파크라인, 측정 횟수. 최근 점수로 필터·정렬 |
| 세션 종료 화면 | 이번 세션의 항목별 평균과 가장 자주 나온 습관 1~2개 |
| 공통 설정 | 분석 켜기/끄기, 실시간 표시 켜기/끄기, 기준값·가중치 조정 |

## 7. 코드 구조 (예정)

```
src/lib/analysis/
  audioAnalyzer.ts     Web Audio + pitchy로 오디오 시계열 수집
  faceAnalyzer.ts      MediaPipe Face Landmarker 초기화·프레임 분석
  headPose.ts          변환 행렬 → yaw/pitch/roll, 시선 방향 계산
  metrics.ts           시계열 → 지표 (끄덕임 검출, 침묵 구간 등)
  scoring.ts           지표 → 점수, 조언 문구
  types.ts             시계열·지표·점수 타입
src/components/
  GazeOverlay.tsx      카메라·재생 영상 위 canvas 오버레이
  AnalysisReport.tsx   다시 듣기 리포트
  Sparkline.tsx        작은 SVG 그래프
public/mediapipe/      wasm 파일과 face_landmarker.task (빌드 시 복사)
```

- 저장 데이터: `Topic.questionMeta`와 별도로 `analysisHistory: Record<질의, AnalysisSummary[]>`를 store에 추가한다.

## 8. 기술적 고려 사항

| 항목 | 내용 | 대응 |
|---|---|---|
| CSP | 현재 `script-src`에 WASM 실행 허용이 없음 | `'wasm-unsafe-eval'` 추가 |
| 오프라인 동작 | MediaPipe는 기본적으로 CDN에서 wasm·모델을 받음 | wasm·모델을 앱에 포함해 로컬에서 로드 |
| 패키지 앱의 file:// | 패키지 앱에서는 `fetch`로 file:// 자원을 못 읽을 수 있음 | 커스텀 프로토콜(`protocol.handle`)로 제공하거나, 모델을 IPC로 읽어 `modelAssetBuffer`로 전달. 프로토타입에서 먼저 확인 |
| 성능 | 녹음·미리보기·분석이 동시에 돎 | GPU 위임 사용, 초당 10~15프레임만 분석, 느리면 Web Worker로 이동 |
| GPU 사용 불가 | 오래된 그래픽·드라이버에서 WebGL2 실패 가능 | GPU 위임 실패 시 **CPU(WASM) 위임으로 자동 전환**. 프레임 처리 시간이 길면 분석 횟수를 자동으로 줄임. 분석이 실패해도 녹음은 계속 |
| 앱 용량 | wasm(약 10MB)과 모델(약 3.6MB) 추가 | 허용 범위. 필요한 wasm 변형만 포함 |
| 정확도 한계 | 안경 반사, 어두운 조명, 옆에 놓인 카메라 | 카운트다운 중 기준 자세 보정, 얼굴 감지율 낮으면 안내 |
| 개인정보 | 얼굴·음성 데이터 | 모두 로컬 처리, 외부 전송 없음 |

## 9. 작업 순서

| 순서 | 작업 | 확인 방법 |
|---|---|---|
| 1 | MediaPipe 프로토타입: 로컬 로드, CSP, 패키지 앱(file://)에서 동작 확인 | `dist:mac:local`로 만든 앱에서 얼굴 점 표시 |
| 2 | FaceAnalyzer + 실시간 시선 오버레이 | 직접 녹화한 얼굴 영상을 가짜 카메라로 넣어 확인 |
| 3 | AudioAnalyzer (음량, 음 높이, 침묵) | 사인파·녹음 파일을 가짜 마이크로 넣어 수치 확인 |
| 4 | metrics.ts, scoring.ts + 단위 테스트 | 합성 시계열(끄덕임 파형, 일정한 음 높이)로 Vitest |

> 변경 기록: 처음에는 끄덕임 기준을 8°에 평활화(EMA)를 넣었으나, 실제 사용에서 끄덕임이 잡히지 않아 4°·평활화 없음·초당 15회로 바꿈. 공통 설정의 "고개 각도·측정 횟수 표시"로 실제 각도를 보며 조정할 수 있음.
| 5 | 다시 듣기 리포트, 영상 재생 오버레이 동기화 | e2e 스크립트 + 스크린샷 |
| 6 | 질의별 점수 기록, 질의 목록의 추이·필터 | store.json 확인 |
| 7 | 설정(분석·오버레이 켜고 끄기, 기준값), README | 수동 확인 |

## 10. 테스트 자료

- 가짜 카메라 기본 영상(초록 화면)에는 얼굴이 없어 시선·고개 분석을 시험할 수 없다.
- 본인 얼굴로 10~20초짜리 짧은 영상(정면 보기, 옆 보기, 끄덕이기 포함)을 녹화해 `.y4m`으로 변환하고 `--use-file-for-fake-video-capture`로 넣는다.
- 음성은 `.wav` 파일을 `--use-file-for-fake-audio-capture`로 넣는다.
- 테스트 자료는 저장소에 올리지 않고 로컬(scratch)에만 둔다.
